## Заплановані можливості

### Нечіткий пошук

Індекс триграм (`Dictionary<int, int[]>`: триграма → відсортовані індекси об’єктів) дає кандидатів,
зокрема й для частини слова в середині назви. Після цього кандидатів перевіряють відстанню
Дамерау–Левенштейна з обмеженням: не більше 1 правки для коротких запитів, не більше 2 для довших.
Кожна правка знижує оцінку, тож нечіткі збіги стоять нижче за наявні типи збігів. Мета: < 300 мкс для
20 результатів.

### Транслітерація

Пошук латиницею (`Kyiv`, `Zaporizhzhia`, `Kamianske`) через окремий ключ, побудований за офіційною
транслітерацією (Постанова КМУ № 55 від 27.01.2010). Зворотна транслітерація неоднозначна, тому
транслітеруються назви в індексі, а запит лише нормалізується. Для ключа буде окремий відсортований
масив, як у наявного індексу назв.

### Порівняння редакцій (`KatottgDiff`)

```csharp
public sealed record KatottgChange(KatottgChangeKind Kind, KatottgUnit? Old, KatottgUnit? New);
public enum KatottgChangeKind { Added, Removed, Renamed, CategoryChanged, Moved }

KatottgDiff diff = KatottgDiff.Compare(oldDataset, newDataset);
```

Об’єкти зіставляються за кодом. Якщо об’єкт переміщено в іншу громаду, міністерство зазвичай видає
новий код, тож пари «видалено + додано» з однаковою назвою і категорією в тій самій області
позначаються як імовірно переміщені. Користувачам це потрібно, щоб перерахувати коди, збережені в
їхніх БД: `KatottgDiff.SuggestReplacement(code)`. CLI отримає
`katottg diff old.xlsx new.xlsx --format md|json|csv`, і цей вивід стане release notes оновлення
даних.

### Джерела оновлень

Бібліотека й далі працюватиме офлайн; оновлення — це плагін, який вмикають за бажанням, а не зашитий
URL:

```csharp
public interface IKatottgSource
{
    ValueTask<KatottgEditionInfo?> GetLatestEditionAsync(CancellationToken ct);
    ValueTask<Stream> OpenAsync(KatottgEditionInfo edition, CancellationToken ct);
}
```

- `GitHubReleaseSource` — готові знімки (`.bin.gz`) з релізів цього репозиторію. Варіант за
  замовчуванням: CI вже імпортував і перевірив офіційний xlsx, а клієнти завантажують ~360 КБ і не
  залежать від HTML сайту міністерства.
- `OfficialSiteSource` — розбирає сторінку міністерства й шукає посилання на `.xlsx` з датою; ретраї,
  `ETag` / `If-Modified-Since`.
- `UrlSource` — пряме посилання, яке налаштовує користувач.
- `FileSource` — локальний файл (тести, офлайн-середовища).

### DI та фонове оновлення

```csharp
services.AddKatottg(o =>
{
    o.UpdateSource = KatottgSources.GitHubReleases();   // або OfficialSite(), Url(...), File(...)
    o.UpdateInterval = TimeSpan.FromDays(1);
    o.CacheDirectory = "/var/cache/katottg";             // останній завантажений знімок
});

public interface IKatottgProvider
{
    KatottgDataset Current { get; }                      // Volatile-читання поля
    event EventHandler<KatottgUpdatedEventArgs> Updated; // з KatottgDiff
}
```

Порядок старту:

1. Завантажити кеш із диска, якщо він новіший за вбудований знімок; інакше взяти вбудований.
2. У фоні запитати джерело.
3. Отримане перевірити: валідатор імпорту, щонайменше 90 % від поточної кількості записів, немає
   критичних помилок.
4. Записати на диск: тимчасовий файл, потім rename.
5. Замінити поточний набір через `Interlocked.Exchange`.

Якщо мережа або джерело недоступні, писати warning у `ILogger` і працювати далі зі старими даними.

### Конвертери

- `JsonConverter<KatottgCode>`, сумісний із source generation System.Text.Json, в окремому від ядра
  пакеті (ядро лишається без `System.Text.Json`).
- `TypeConverter` для прив’язки конфігурації та model binding в ASP.NET Core.
- EF Core `ValueConverter<KatottgCode, string>` у `UkrUtils.Katottg.EntityFrameworkCore`.

### Автоматичне оновлення даних

Щотижнева GitHub Action перевіряє сайт міністерства. Коли з’являється нова редакція, вона відкриває PR
з новим xlsx в `OfficialData/`, перебудованим знімком і diff. Людина переглядає й зливає його, а потім
випускає нову версію пакета.

CLI також може отримати експорт у JSON / CSV для тих, кому дані потрібні поза .NET.

## Відкриті питання

1. **КОАТУУ ↔ КАТОТТГ.** Багато старих систем досі зберігають коди КОАТУУ. У кодифікаторі
   відповідності немає, і офіційних таблиць відповідності теж немає, є лише неофіційні (наприклад,
   від Казначейства). Якщо вона знадобиться, це буде окремий пакет `UkrUtils.Katottg.Koatuu`.
2. **Історія редакцій.** Чи має бібліотека відповідати на питання «який код був у цього села на дату
   X»? Тоді треба тримати всі знімки з `OfficialData/` і додати `KatottgHistory`.
3. **Окуповані території.** Чи потрібен прапорець «тимчасово окупована / бойові дії»? Цей перелік
   окремо публікує Мінреінтеграції, у кодифікатор він не входить. Для АР Крим і Севастополя примітка у
   файлі вже дає `IsTemporarilyNotInForce`.
4. **Старіші версії .NET.** Чи потрібен `netstandard2.0`, наприклад для .NET Framework? Тоді
   доведеться відмовитися від `ISpanParsable` і частини оптимізацій або тримати багатоцільову збірку.
5. **Ліцензія даних.** Держстат публікує матеріали за CC BY 4.0. Атрибуцію треба додати в README і в
   метадані пакета.
