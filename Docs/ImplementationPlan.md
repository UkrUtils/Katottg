# UkrUtils.Katottg — план реалізації

Бібліотека .NET для роботи з Кодифікатором адміністративно-територіальних одиниць та територій
територіальних громад (КАТОТТГ): пошук, ієрархія, валідація кодів, оновлення з офіційних джерел.

Цільова платформа: `net10.0` (вже задана в `UkrUtils.Katottg.csproj`). Мова: C# latest, nullable увімкнено.

---

## 1. Що в файлі `OfficialData/katottg-26-11-03.xlsx`

### 1.1 Фізична структура

| Що | Значення |
|---|---|
| Аркуші | один, `Кодифікатор` |
| Рядок 1 | гриф «ЗАТВЕРДЖЕНО наказом … від 26.11.2020 № 290 (в редакції наказу … від 12.01.2021 № 3)» — у колонці F, з `\n` всередині |
| Рядок 2 | заголовок «Кодифікатор адміністративно-територіальних одиниць…» |
| Рядок 3 | шапка колонок (A–G): `Перший рівень`, `Другий рівень`, `Третій рівень`, `Четвертий рівень`, `Додатковий рівень`, `Категорія об’єкта`, `Назва об’єкта` |
| Рядки 4–31754 | дані: **31 751 запис** |
| Рядок 31755 | «Примітка. Коди Автономної Республіки Крим … набирають чинності з моменту повернення …» |
| Розмір | 1.5 МБ xlsx; 10 МБ `sheet1.xml`; 1.8 МБ `sharedStrings.xml` |

Кожен рядок — це **повний шлях** до об’єкта: колонки рівнів 1…N заповнені кодами всіх предків
і самого об’єкта, решта порожні. Код самого об’єкта — це останній заповнений рівень.
Пропусків між рівнями немає.

### 1.2 Категорії і рівні

| Категорія | Значення | Рівень | Кількість |
|---|---|---|---|
| `O` | область / АР Крим | 1 | 25 |
| `K` | місто зі спеціальним статусом (Київ, Севастополь) | 1 | 2 |
| `P` | район | 2 | 136 |
| `H` | територія територіальної громади | 3 | 1 772 |
| `M` | місто | 4 | 459 |
| `T` | селище міського типу | 4 | 881 |
| `X` | селище | 4 | 1 164 |
| `C` | село | 4 | 27 204 |
| `B` | район у місті | 5 (додатковий) | 108 |

Літери категорій у цьому файлі — **латиниця** (U+0043 тощо). Вони візуально збігаються з
кирилицею (С, Н, Х, Т, М, Р, В, О, К), тому парсер має приймати обидва варіанти.
Категорію `T` закон про скасування СМТ поступово прибирає, тож у моделі не можна вважати набір
категорій закритим: потрібне значення `Unknown` для літер, яких ми ще не знаємо.

### 1.3 Формат коду

`UA` + 17 цифр, наприклад `UA01020030010043419`:

```
UA 01 02 003 001 00 43419
   │  │  │   │   │  └─ 5 цифр: службовий хвіст (не виводиться з ієрархії)
   │  │  │   │   └──── район у місті (01..)
   │  │  │   └──────── населений пункт у громаді (001..)
   │  │  └──────────── громада в районі (001..)
   │  └─────────────── район в області (01..)
   └────────────────── область (01..85)
```

Що перевірено на всіх 31 751 записі:
- усі коди відповідають `^UA\d{17}$`;
- коди об’єктів унікальні;
- **12 значущих цифр** (без 5-значного хвоста) теж унікальні. Тому можна шукати за кодом,
  у якому хвіст неправильний або втрачений;
- префікс коду дитини завжди збігається з префіксом батька. Батька можна знайти так: обнулити
  найнижчий ненульовий сегмент і знайти запис із таким 12-значним префіксом. Батьківський
  код повністю, разом із хвостом, з самого коду дитини не обчислити.

### 1.4 Нетипові місця в ієрархії (16 рядків)

1. **Київ, Севастополь (`K`)**: рівні 1–4 мають однаковий код міста, а райони міста (`B`)
   лежать на рівні 5. Районів області і громад у них немає.
2. **Прип’ять, Чорнобиль (`M`)**: лежать прямо під Київською областю, рівні 2–3 повторюють код
   області. Це зона відчуження, у ній немає району і громади.
3. **Райони у містах (`B`)** є не лише в Києві й Севастополі. Ще в 22 містах вони вкладені
   під `M`: Харків, Дніпро, Донецьк, Кривий Ріг, Запоріжжя, Львів та інші.

Висновок: ієрархію треба будувати з **унікальних кодів** у рядку. Номер колонки для цього не
годиться: «рівень 3» не завжди означає громаду.

### 1.5 Проблеми якості даних

| Проблема | Кількість | Що робити |
|---|---|---|
| Пробіл у кінці назви | 319 (313 з них — у `H`) | `Trim()` під час імпорту |
| Латинська `i` замість `і` | 1 (`Вiйтовецька`) | зберегти оригінал; у ключі пошуку замінювати латинські двійники на кириличні |

| Службові рядки (гриф, шапка, примітка) | 4 | шукати шапку за текстом, а не за номером рядка |

## 2. Принципи дизайну

1. **Працює одразу після встановлення.** Пакет містить вбудований знімок даних (~420 КБ gzip).
   Мережа для старту не потрібна.
2. **Дані незмінні.** `KatottgDataset` — immutable. Оновлення створює новий екземпляр і
   атомарно підміняє його. Читачам блокування не потрібні.
3. **Код — головний ключ.** `KatottgCode` — це `readonly struct` поверх `ulong`
   (17 цифр < 2^64): без алокацій, швидке порівняння.
4. **Ядро без залежностей.** Парсер xlsx пишемо на `System.IO.Compression.ZipArchive` +
   `XmlReader` (OOXML — це zip із XML). ClosedXML / EPPlus не потрібні. Це ~200 рядків.
5. **Пошук без зовнішніх рушіїв.** На 31 тис. записів достатньо власних індексів у пам’яті.
   Lucene тут зайвий.
6. **Дружність до AOT і trimming.** Без рефлексії та без `System.Text.Json` у ядрі.

## 5. Зберігання і завантаження

### 5.1 Бінарний знімок `katottg.bin.gz`

Простий формат, щоб читати його швидко й без рефлексії:

```
magic "KATG" | version u16 | edition-date i32 | sha256[32]
count u32
string-table:  u32 count, далі UTF-8 рядки з префіксом довжини (унікальні назви, ~17.6 тис.)
records:       count × { code u64, parentIndex i32, category u8, nameIndex u32 }
```

- Читання: `GZipStream` → `BinaryReader`, потім один прохід, щоб зібрати дерево.
  Мета — **< 30 мс** холодного старту і < 15 МБ у керованій пам’яті.
- Знімок генерує `katottg build-snapshot OfficialData/katottg-XX-XX-XX.xlsx` у CI. Це
  `EmbeddedResource`; розробник руками його не редагує.
- Версію пакета NuGet підвищуємо, коли змінюється вбудована редакція. Дату редакції пишемо в
  `PackageReleaseNotes` і в `KatottgEdition`.

### 5.2 Чому не JSON / SQLite

JSON удвічі-втричі більший, і для швидкого розбору йому потрібен STJ source generator.
SQLite додає нативну залежність. Для 31 тис. рядків, які читаються один раз, обидва варіанти
зайві. Експорт у JSON/CSV можна зробити в CLI для тих, кому треба.

## 6. Пошук

### 6.1 Нормалізація (ключ пошуку)

Застосовується однаково до назв під час індексації і до запиту користувача:

1. `Trim`, нижній регістр (`ToLowerInvariant`).
2. Латинські двійники → кирилиця (`i→і`, `a→а`, `e→е`, `o→о`, `c→с`, `p→р`, `x→х`, `y→у`),
   **лише в словах зі змішаним алфавітом**, як-от `Вiйтовецька`. Слово, повністю написане
   латиницею, — це транслітерація; його передаємо в транслітераційний індекс без змін.
3. Усі апострофи (`'`, `’`, `ʼ`, `` ` ``, `‘`) → один символ `ʼ`, або взагалі прибрати:
   тоді «Кам’янське» = «Камянське». Варіант задаємо в опціях; за замовчуванням — прибирати.
4. Дефіси, крапки, кілька пробілів поспіль → один пробіл.
5. `ґ→г`, `ё→е`, `ы→и`, `э→е`, `ъ→ʼ` — терпимість до російської розкладки і помилок.
6. Обрізати службові префікси в запиті: `м.`, `с.`, `смт`, `с-ще`, `селище`, `село`, `місто`,
   `обл.`, `область`, `р-н`, `район`, `громада`, `ТГ`, `ОТГ`. Вони стають **фільтром за
   категорією**, а не частиною тексту.

Окремий **транслітераційний ключ** за офіційною транслітерацією (Постанова КМУ № 55 від 27.01.2010)
дає змогу шукати латиницею: `Kyiv`, `Zaporizhzhia`, `Kamianske`. Для довідки: зворотна
транслітерація неоднозначна, тому транслітеруємо назви в індексі, а запит лише нормалізуємо.

### 6.2 Індекси

| Індекс | Структура | Для чого |
|---|---|---|
| `code → unit` | `Dictionary<ulong, int>` | точний пошук за кодом |
| `significant12 → unit` | `Dictionary<ulong, int>` | пошук без хвоста |
| `normalizedName → int[]` | `Dictionary<string, int[]>` | точний збіг назви |
| префікси | відсортований масив `(key, index)` + бінарний пошук | автодоповнення «Київ…» |
| триграми | `Dictionary<int, int[]>` (триграма → відсортовані індекси) | нечіткі збіги, частина слова в середині назви |
| транслітерація | як «префікси», окремий масив | латиниця |

Префіксний індекс на відсортованому масиві простіший і компактніший за trie, а для 31 тис.
записів працює так само швидко. Триграми дають кандидатів для нечіткого пошуку, після чого
рахуємо відстань Дамерау–Левенштейна з обмеженням (≤ 1 для коротких запитів, ≤ 2 для довших).

### 6.3 Ранжування

Оцінка для кожного кандидата, від кращого до гіршого:

1. точний збіг нормалізованої назви;
2. збіг префікса;
3. збіг на початку слова («Кам’янка» в «Кам’янка-Бузька»);
4. підрядок;
5. нечіткий збіг (штраф за кожну правку).

Додаткові ваги: важливість категорії (`K` > `M` > `T`/`X` > `C`), а для однакових назв — місто
перед селом. Якщо задано контекст (область, район), записи поза ним відкидаються.

### 6.4 Структурований і «вільний» запит

```csharp
// Структурований
var hits = dataset.Search(new KatottgQuery
{
    Name = "Андріївка",
    Region = "Запорізька",           // теж нечіткий збіг
    District = "Бердянський",
    Categories = [KatottgCategory.Village],
    Limit = 20,
});

// Вільний рядок: розбити по комах, розпізнати маркери категорій і рівнів
var hits2 = dataset.Search("с. Андріївка, Бердянський р-н, Запорізька обл.");
```

Розбір вільного рядка: кожна частина після коми отримує роль за маркером (`обл.`, `р-н`,
`громада`, `с.`). Якщо маркера немає, частину пробуємо як назву на кожному рівні. Перемагає
ієрархічно узгоджена комбінація з найвищою сумарною оцінкою. Цим розв’язується головна
практична задача: знайти код за адресою з довільного тексту.

```csharp
public sealed record KatottgSearchHit(KatottgUnit Unit, double Score, MatchKind Kind);
```

### 6.5 Цільова швидкість (BenchmarkDotNet, Apple M-серія)

## 7. Оновлення з офіційних джерел

### 7.1 Джерела

- Відповідальний — **Міністерство розвитку громад та територій України** (Мінрозвитку).
  Сторінка кодифікатора зараз лежить на домені `mininfra.gov.ua`:
  `https://mininfra.gov.ua/diialnist/rozvytok-mistsevoho-samovriaduvannia/kodyfikator-administratyvno-terytorialnykh-odynyts-ta-terytorii-terytorialnykh-hromad`.
  Там публікуються редакції у вигляді xlsx (за пошуком: «Кодифікатор 22.06.2026», «Кодифікатор 07.07.2026»).
- Накази про зміни — на `zakon.rada.gov.ua`, наприклад `v0042945-25`.
- Опис і чинна редакція — на сайті Держстату: `https://ukrstat.gov.ua/klasf/nac_kls/tab_kato.htm`.
- Окремого машиночитаного набору (JSON/API) на data.gov.ua я не знайшов.

**Важливо:** під час планування сторінка міністерства відповідала HTTP 522 (таймаут Cloudflare).
Домен уже змінювався (minregion → mtu → mininfra), формат посилань теж може змінитися. Тому:

- бібліотека **ніколи не залежить від мережі** під час виконання; знімок вбудований;
- джерело оновлень — це **плагін** (`IKatottgSource`), а не зашитий URL;
- перевіряємо наявність нової редакції ще й у CI репозиторію. Вихідний xlsx зберігаємо в
  `OfficialData/` як архів: це страховка на випадок, якщо сайт буде недоступний.

### 7.2 Абстракції

```csharp
public interface IKatottgSource
{
    ValueTask<KatottgEditionInfo?> GetLatestEditionAsync(CancellationToken ct);
    ValueTask<Stream> OpenAsync(KatottgEditionInfo edition, CancellationToken ct);
}

// Реалізації:
//  OfficialSiteSource — парсить HTML сторінки міністерства, шукає <a href> на .xlsx з датою
//                       у тексті/імені файлу; Polly-ретраї, ETag/If-Modified-Since.
//  UrlSource          — пряме посилання (налаштовує користувач).
//  FileSource         — локальний файл (тести, офлайн).
//  GitHubReleaseSource — готові знімки .bin.gz з релізів цього репозиторію (найнадійніше).
```

`GitHubReleaseSource` зручний за замовчуванням: CI сам імпортує й перевіряє офіційний xlsx, а
клієнти завантажують готовий знімок на 420 КБ. Тоді вони не залежать від стабільності HTML
сайту міністерства.

### 7.3 Імпорт xlsx (`KatottgSheetParser`)

1. Відкрити zip і знайти `xl/workbook.xml`, а в ньому перший аркуш. Назву «Кодифікатор» не
   вважати обов’язковою.
2. Прочитати `sharedStrings.xml` у `string[]`.
3. Потоково читати `sheet1.xml` через `XmlReader`. Підтримати комірки `t="s"`,
   `t="inlineStr"`, `t="str"` і числові.
4. Знайти рядок шапки, у якому є «Перший рівень» і «Назва об’єкта». За шапкою визначити
   колонки, бо порядок може змінитися.
5. Рядок даних — це рядок, де перша колонка відповідає `^UA\d{17}$`. Усе інше пропускаємо,
   але повідомляємо в `ImportReport`: гриф, примітка, порожні рядки.
6. Код об’єкта — останній заповнений рівень. Батько — останній **відмінний** від нього
   код ліворуч. Так коректно обробляються повтори кодів у Києві, Севастополі та Прип’яті.
7. Перевірки, з помилкою або попередженням у звіті:
   - коди унікальні; 12 значущих цифр унікальні;
   - батько існує і з’явився раніше;
   - префікс дитини узгоджений із префіксом батька;
   - категорія відома й допустима для свого рівня;
   - у назві є латинські символи; є пробіли по краях.
8. Дата редакції береться з імені файлу (`katottg-YY-MM-DD`), а якщо не вдалося — з
   `docProps/core.xml` (`dcterms:modified`). Також зберігаємо SHA-256 вихідного файлу.

Розбір 10-мегабайтного XML потоком має займати < 1 с.

### 7.4 Порівняння редакцій (diff)

```csharp
public sealed record KatottgChange(KatottgChangeKind Kind, KatottgUnit? Old, KatottgUnit? New);
public enum KatottgChangeKind { Added, Removed, Renamed, CategoryChanged, Moved }

KatottgDiff diff = KatottgDiff.Compare(oldDataset, newDataset);
```

Записи зіставляються за кодом. Якщо об’єкт переміщено в іншу громаду, міністерство зазвичай
видає новий код. Тому окремо шукаємо пари «видалено + додано» з однаковою назвою і категорією
в тій самій області й позначаємо їх `ProbablyMoved`. Користувачам це потрібно, щоб
перерахувати збережені коди в своїх БД. Для цього є `KatottgDiff.SuggestReplacement(code)`.

Diff також виводить CLI: `katottg diff old.xlsx new.xlsx --format md|json|csv`. Цей вивід
використовуємо як release notes пакета.

### 7.5 Оновлення під час роботи застосунку (DI)

```csharp
services.AddKatottg(o =>
{
    o.UpdateSource = KatottgSources.GitHubReleases();   // або OfficialSite(), Url(...), File(...)
    o.UpdateInterval = TimeSpan.FromDays(1);
    o.CacheDirectory = "/var/cache/katottg";             // останній завантажений знімок

    event EventHandler<KatottgUpdatedEventArgs> Updated; // з KatottgDiff
}
```

Порядок старту:

1. Завантажити кеш із диска, якщо він новіший за вбудований знімок.
2. Інакше взяти вбудований знімок.
3. У фоні запитати джерело.
4. Отримане перевірити: валідатор імпорту, кількість записів не менша за 90 % від поточної,
   немає критичних помилок.
5. Записати на диск: тимчасовий файл, потім rename.
6. Замінити поточний набір через `Interlocked.Exchange`.

Якщо мережа або джерело недоступні, писати warning у `ILogger` і працювати далі зі старими
даними.

## 8. Тестування

- **Моделі/код:** `Parse`/`TryParse`/`ToString` проходять туди й назад для всіх 31 751 кодів;
  некоректні входи; сегменти; `ParentPrefix`.
- **Імпорт:** зменшений фікстурний xlsx на ~50 рядків. Він має покривати АРК, Київ із районами,
  Прип’ять, місто з районами (Харків), назви з пробілом у кінці, латинською `i`, апострофами.
  Повний офіційний файл використовуємо в окремому інтеграційному тесті.
- **Ієрархія:** інваріанти на повному наборі: у кожного некореневого запису є батько; глибина
  ≤ 5; `B` лежить тільки під `M`/`K`; `H` — тільки під `P`; кількості категорій збігаються з
  таблицею з п. 1.2.
- **Пошук:** набір запитів із відомими відповідями («Кривий Ріг», «кривий-ріг», «Kryvyi Rih»,
  «Камянське», «Вiйтовецька» латиницею, «Андріївка, Бердянський» тощо). Тести на ранжування:
  місто вище за однойменне село.
- **Diff:** дві синтетичні редакції з відомими змінами.
- **Snapshot:** `Save` → `Load` дає побайтово ідентичний результат; детермінований вивід,
  щоб у git не було зайвих змін.
- **Бенчмарки:** операції з п. 6.5 і холодний старт `KatottgDataset.Embedded`.

## 10. Відкриті питання

1. **КОАТУУ ↔ КАТОТТГ.** Багато старих систем досі зберігають КОАТУУ. У цьому файлі
   відповідності немає. Чи потрібна вона? Офіційних таблиць відповідності немає, є лише
   неофіційні (наприклад, від Казначейства). Якщо потрібна — окремий пакет `UkrUtils.Katottg.Koatuu`.
2. **Історія редакцій.** Чи треба вміти відповідати на питання «який код був у цього села на
   дату X»? Якщо так, тримати всі знімки з `OfficialData/` і зробити `KatottgHistory`.
3. **Окуповані території.** Чи потрібен прапорець «тимчасово окупована / бойові дії»? Це окремий
   перелік Мінреінтеграції, у кодифікаторі його немає. Для АРК і Севастополя примітка у файлі
   вже дає `IsTemporarilyNotInForce`.
4. **Нижчі версії .NET.** Чи потрібен `netstandard2.0`, наприклад для .NET Framework? Тоді
   доведеться відмовитися від `ISpanParsable` і частини оптимізацій або тримати багатоцільову збірку.
5. **Ліцензія даних.** Держстат публікує матеріали за CC BY 4.0. Атрибуцію треба додати в README
   і в метадані пакета.
